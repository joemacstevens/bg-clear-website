# 2026-10-07 — Where do the emails actually go?

## What happened

Joe asked a simple-sounding question: check that all email notifications go to Evans. The answer turned out to be "almost none of them do, and the ones Evans cares about most don't send at all."

First snag: the session's worktree was cut from `main`, which is stuck back at the May 29 branding merge. No email code there at all. A first pass came back empty, which could've been read as "there are no notifications." Digging through branches showed all the Resend work lives on `fix/invoice-payments` (PR #27), which is also what production is deployed from via CLI.

Mapped every send site (10 templates). Customer emails go to customers, fine. Staff alerts were a patchwork: some to the assigned rep, some to `INTERNAL_NOTIFY_EMAIL`, some to both. Locally that var was still `joemac@ajeo.design` from the Resend sandbox days. In Vercel it was a sensitive var, so `vercel env pull` came back blank and we genuinely couldn't see what it was set to.

## The conversation

Reported back and flagged the address: Joe had typed `evens@bg-clear.com`, but the domain is `bgclear.com` with no hyphen. Joe confirmed `evans@bgclear.com`. His reaction was the real finding: "Oh wow! I thought those invoices were going through Forms for You." He'd assumed invoices and payment receipts were handled somewhere else. What he actually wants is for Evans to get the invoices and payment receipts.

Then the bigger gap showed up. The pay-invoice links built in July (rep generates a link → client pays via Woo/CyberSource) send **zero** email. The Woo webhook flips `manual_invoices.status` to paid, logs a line, and returns. So nobody was ever told an invoice was issued or paid unless they went and looked at `/rep/invoices`.

## Decisions

- Two new emails: **"Invoice sent"** (when a rep or admin generates a link) → internal inbox; **"Payment received"** (webhook, fires once thanks to the existing idempotent guard) → internal inbox + the rep who issued it.
- Added `staffRecipients()` to merge the internal inbox with rep emails, without duplicates. Also swapped it into the existing portal order-paid alert.
- Set `INTERNAL_NOTIFY_EMAIL=evans@bgclear.com` in Vercel Production, this time **non-sensitive**, so it can be read back next time anyone asks this question.
- Confirmed via the Resend API that `bgclear.com` is a verified sending domain, so mail to Evans will actually deliver (the sandbox sender only reaches the account owner).
- Didn't send a real test email to Evans. Rendered both templates locally with a mocked fetch instead.

## Problems/Bugs

- `manual_invoices` isn't in `database.types.ts`, so every query on it types as `never` (part of ~466 pre-existing svelte-check errors). Cast the new invoice row `as any` to match the file's existing pattern, rather than regenerating types in this change.
- The build failed in the fresh worktree because there's no `.env` (static `$env` imports). Built fine with placeholder values.
- Almost chained a `git checkout -- .` onto a check command by mistake; the auto-mode classifier blocked it before it wiped the edits. Good catch by the guardrail.
