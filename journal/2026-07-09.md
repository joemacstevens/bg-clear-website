# 2026-07-09 — Pay-invoice links (rep/admin generated)

## What happened

Joe forwarded a screenshot of a text thread with Evens. Evens wants a "pay your
invoice link" on the site so that when a rep sends a B2B client their invoice,
there's a link to pay it. Joe had set `www.bgclear.com/pay-invoice` as a
placeholder and asked Evens for the "real WooCommerce payment page URL."

First thing I did was untangle the mental model. Evens (and the placeholder)
imagine one static pay page. That's not how our setup works — there's no such
page, and payment is per-order: each order gets a unique Woo `order-pay` URL
minted at creation time, and CyberSource collects the card there. Explained that
to Joe.

Joe came back with: "Can we set up a page like that? There are unique
circumstances where they want to do that." So — a real ad-hoc invoice, not tied
to the quote→order pipeline (phone orders, deposits, ARs they're chasing).

Asked two scoping questions. Answers: **arbitrary amount**, and **rep/admin
generates the link** (customer just clicks & pays — never types the amount).
That's the clean version. Joe said "yes build a now" (option A — link points
straight at Woo, skip the branded bgclear.com landing for now).

## Decisions

- An invoice = a Woo order with ONE fee line for the amount. Reuse
  `createWooOrder` almost as-is. The whole payment path (CyberSource + paid
  webhook) already exists, so this was mostly plumbing + a table + a form.
- New `manual_invoices` table rather than overloading `orders` (orders has too
  many required FKs and a fulfillment lifecycle that doesn't apply here).
- Tag the Woo order with `bg_type: 'manual_invoice'` meta so the paid-webhook
  knows to reconcile the invoice table instead of orders.
- Lives under the rep portal (`/rep/invoices`, nav label "Pay Links") since
  Evens explicitly said the *sales rep* sends these. Staff-only RLS covers admin
  too.

## Built

- Migration `20260709000001_manual_invoices.sql` (table + staff RLS via
  `private.current_user_role()`).
- `createWooOrder` gained an optional `orderType` → emits `bg_type` meta.
- `/rep/invoices` page: generate form (amount, description, optional invoice #,
  client name/email) → creates pending Woo order → shows pay link with a copy
  button. List of prior invoices with pending/paid status badges + copy-link.
  Server action inserts the row first, then creates the Woo order, and rolls the
  row back if Woo is unreachable.
- Webhook `/api/webhooks/woocommerce` extended: manual-invoice orders flip
  `manual_invoices.status` to paid (idempotent), separate from the orders path.
- `vite build` passes clean.

**Then Joe asked for option B too** ("so the link is on your domain"). Added a
standalone public route `src/routes/pay-invoice/[token]/` (outside all route
groups → root layout only, no portal auth, no marketing nav). The invoice uuid
IS the bearer token in the URL. Load fetches via the service-role admin client
(RLS blocks anon) and exposes only payer-safe fields (no email). Branded card:
BG Clear logo, invoice #, description, amount, "Pay securely" button that
forwards to the Woo/CyberSource checkout. Handles paid/void states. The rep's
Copy buttons now copy `bgclear.com/pay-invoice/{id}` instead of the raw Woo URL.
